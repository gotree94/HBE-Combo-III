### 핵심 관찰

- **최대/최소 지연이 동일**: 두 설계 모두 I→Z 최대 `15.179ns`, 최소 `7.907ns`.
- **지연 값 분포가 거의 동일**: 입력별 값이 재배치된 형태로 나타나며, 구조적 차이가 최종 I/O 지연에 크게 반영되지 않음.
- **S 입력도 값 집합이 유사**: S 비트별 지연이 같은 값군(`10.259, 12.655, 12.771, 14.945`)으로 나타남.
- **일부 경로의 RF/FR 공란**: 해당 입력의 상승/하강 전파가 보고되지 않거나 단측 전파 특성으로 해석될 수 있음(보고 형식/경로 unateness 확인 필요).

## 2. IF에 최장 경로가 있어도 차이가 크지 않은 이유 유추

### 2.1 RTL 구조와 FPGA 구현의 차이

| 관점 | IF (`if-else if`) | CASE (`case`) |
|---|---|---|
| RTL 의미 | 우선순위(priority) 선택 구조. 코드상 최상위 조건이 먼저 평가됨 | 병렬 선택 구조로 기술됨 |
| 이산 게이트 구현 시 예상 | 우선순위 체인이 길어지면 최장 경로가 커질 수 있음 | 비교/선택이 상대적으로 균등할 수 있음 |
| FPGA 실제 구현 | LUT + 인터커넥트로 매핑, 합성 최적화로 동등 논리화 가능 | LUT + 인터커넥트로 매핑 |

IF 문은 ASIC/이산 게이트 관점에서는 priority chain 때문에 경로 차이가 커질 수 있습니다. 하지만 FPGA(Cyclone II)에서는 조합논리가 **LUT(Look-Up Table)** 단위로 구현됩니다.

### 2.2 FPGA 지연 구성

게이트레벨/타이밍 보고의 I→Z 지연은 대략 다음 성분의 합입니다.

```text
Input Pin Delay + Input Buffer + Interconnect + LUT(Cell) Delay + Interconnect + Output Buffer + Output Pin Delay
```

- **LUT 지연**: LUT는 입력 조합에 대해 진리표 기반으로 출력. 동일 LUT 내부 입력 간 지연 차이는 이산 게이트 체인만큼 크지 않음.
- **인터커넥트/IO 지연 지배**: FPGA에서는 배선(interconnect)과 IO 버퍼 지연 비중이 큽니다. 개별 AND 게이트 시뮬레이션의 7~17ns 수준 범위 감각과 비교하면, 실제 FPGA 경로는 “게이트 몇 단”보다 “핀-배선-LUT-배선-핀” 전체 경로가 지연을 결정합니다.
- **합성 최적화**: Quartus는 CASE/IF의 논리 기능이 동일하면 공통 논리로 최적화합니다. 결과적으로 두 RTL이 유사한 LUT 네트워크로 매핑될 수 있습니다.

### 2.3 본 결과에 대한 해석

- 최대/최소가 동일하고 값 분포가 유사한 것은, **IF의 priority 구조가 그대로 긴 게이트 체인으로 보존되지 않고 LUT 기반으로 재구성**되었음을 시사합니다.
- 입력별 지연 차이는 논리 깊이보다는 **입력 핀 위치, 라우팅 경로, 배치 결과, 출력까지의 인터커넥트** 영향이 큽니다.
- 따라서 "IF가 최장 경로를 가질 것"이라는 RTL 직관은 FPGA 합성/배치·배선 이후에는 크게 완화될 수 있습니다.

## 3. Quartus II UI에서 확인하는 방법

아래는 Quartus II 13.0sp1 기준 메뉴 명칭입니다. (버전에 따라 일부 명칭이 약간 다를 수 있음)

### 3.1 컴파일

1. `File > Open Project...`로 해당 프로젝트 열기.
2. 타깃 디바이스가 의도한 FPGA인지 확인: `Assignments > Device...`.
3. `Processing > Start Compilation` 실행.
4. 완료 후 `Compilation Report`에서 오류/경고 확인.

### 3.2 RTL Viewer로 논리 구조 확인

1. `Tools > Netlist Viewers > RTL Viewer`.
2. `CH2_16MUX_CASE`, `CH2_16MUX_IF` 각각 열어 비교.
3. 확인 포인트:
   - IF가 priority 체인으로 남아 있는지, 또는 mux/logic으로 정리됐는지.
   - CASE와 IF의 상위 논리 구조가 유사한지.

> RTL Viewer는 합성 전후의 논리 표현에 가깝습니다. 실제 FPGA 자원 매핑은 Technology Map Viewer에서 확인합니다.

### 3.3 Technology Map Viewer로 LUT 매핑 확인

1. `Tools > Netlist Viewers > Technology Map Viewer (Post-Mapping)` 또는 `Technology Map Viewer (Post-Fitting)`.
2. 모듈 내부를 확대해 LUT/LCELL/IO atom 확인.
3. 확인 포인트:
   - 조합논리가 `cycloneii_lcell_comb`(LUT)로 어떻게 분해됐는지.
   - CASE/IF의 LUT 개수, 연결 구조, 출력까지 단계 수 비교.
   - Post-Fitting에서 실제 배치 후 연결 확인.

### 3.4 전파 지연(Propagation Delay) 확인

**Classic Timing Analyzer를 사용하는 경우:**

1. `Compilation Report` 열기.
2. `Timing Analyzer` > `Propagation Delay` 또는 `tppd`/`Delays` 관련 항목 확인.
3. 입력(I0~I15, S[0]~S[3]) → 출력(Z) 경로의 RR/RF/FR/FF 확인.

**TimeQuest를 사용하는 경우:**

1. `Tools > TimeQuest Timing Analyzer`.
2. `Report Datasheet` 또는 `Reports > Datasheet > Report Datasheet`.
3. 또는 `Reports > Custom Reports > Report Paths`에서 From=`I* S*`, To=`Z` 설정 후 지연 확인.

### 3.5 경로 상세 확인

1. Timing 결과에서 특정 경로(예: 최대 지연 경로, 최소 지연 경로) 선택.
2. 우클릭 후 `Locate Path` / `Locate in Technology Map Viewer` / `Chip Planner` 사용.
3. 확인 포인트:
   - 지연이 LUT cell에서 발생하는지, interconnect에서 발생하는지.
   - 최소 지연 경로와 최대 지연 경로의 배선 길이/IO 위치 차이.

### 3.6 자원 사용량 비교

1. `Compilation Report > Fitter > Resource Section > Resource Usage Summary`.
2. CASE/IF 각각 컴파일한 프로젝트/리비전에서 LE, LUT 입력 수, 팬인/팬아웃 등을 비교.
3. 필요 시 `Analysis & Synthesis > Resource Utilization by Entity` 확인.

## 4. 결론

- IF 문은 RTL 코드상 우선순위 구조를 갖지만, Cyclone II FPGA에서는 LUT 기반으로 합성/매핑되면서 그 구조적 차이가 최종 지연 차이로 크게 나타나지 않을 수 있습니다.
- 본 측정 결과는 CASE/IF의 최대·최소 지연이 동일하고 분포가 유사하여, **지연이 논리식 형태 자체보다 LUT/인터커넥트/IO 배치·배선 결과에 더 크게 영향받음**을 보여줍니다.
- 최종 확인은 Quartus II의 **RTL Viewer, Technology Map Viewer(Post-Mapping/Post-Fitting), Timing Analyzer/TimeQuest 경로 보고서**로 수행하는 것이 가장 확실합니다.
