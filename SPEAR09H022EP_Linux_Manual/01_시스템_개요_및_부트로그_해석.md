# 01. 시스템 개요 및 부트로그 해석

> 대상: STMicroelectronics SPEAR09H022EP (SPEARHead 아키텍처 기반)
> 플랫폼 이름: `STM-spearhead`, 커널 이미지명: `Linux-2.6.10_dev-versatile926ejs`

---

## 1. 하드웨어 개요 (부트로그에서 확인된 사항)

| 항목 | 값 | 출처 |
|---|---|---|
| CPU | ARM926EJ-S rev 4 (ARMv5TEJ), 코어 ID `41069264` | `CPU: ARM926EJ-Sid(wb)` |
| I-Cache | 32,768 B (assoc 4, 32B line, 256 sets) | 부트로그 |
| D-Cache | 16,384 B (assoc 4, 32B line, 128 sets) | 부트로그 |
| RAM | 32 MB (Bank#0 at 0x00000000) | `RAM Configuration` |
| Flash | ST M25P64 SPI 시리얼 NOR 8MB x 2 | MTD 로그 |
| 콘솔 | UART1 (`ttyS0`), irq 21 | ttyS 로그 |
| UART 추가 | ttyS1(irq20), ttyS2(irq19) | ttyS 로그 |
| Timer | TICK_RATE 66.5 MHz (`66500000`) | timer 로그 |
| Ethernet | ST SPEARHEAD Ethernet Driver v0.1, MII PHY ID 0x00111c04 | eth 로그 |
| USB | OHCI 2포트: 0xf000a000 irq6, 0xf000e000 irq7 | ohci 로그 |
| RTC | Real Time Clock Driver (초기화됨) | RTC 로그 |
| FPU | NetWinder (soft-float) 에뮬레이터 | 부트로그 |

> 참고: 코어 ID `41069264` = ARM926EJ-S (r4p3 계열). ARM은 빅엔디안 지원
> (armeb)도 있으나 본 보드는 리틀엔디안으로 동작("EEP, Data cache writeback").

## 2. 메모리 맵 (RAM)

- U-Boot 코드: 0x81208800 ~ 0x81239BC8  (BSS: ~0x8124FD84)
- 커널 로드/진입 주소: `Load Address 00008000`, `Entry Point 00008000`
- 커널 이미지 저장 위치(플래시): 0x00070000, U-Boot는 0x16070000으로 로드 후 `bootm`
- initrd 로드 주소(RAM): `0x00800040` (크기 7MB 한도)
- 사용 가능 RAM: 32MB 총 용량 중 22,304KB (커널 2205K code ...)

> U-Boot는 커널보다 **상위 주소(0x8120xxxx)**에 배치되어 있어 커널 진입
> (0x8000)과 충돌하지 않음. initrd는 0x800040에, 커널은 0x8000에 로드되므로
> initrd = 커널 이미지 직후 배치되어도 겹치지 않습니다.

## 3. 플래시 파티션 맵 (부트로그 기준)

### 3-1. 첫 번째 ST M25P64 (8MB, SPI flash #0)

SPIFLASH: "STW Serial Flash" 드라이버(`stserialflash`류)가 정적 파티셔닝 적용

| 영역 | 오프셋 | 크기 | 레이블 | 용도 |
|---|---|---|---|---|
| 0 | 0x00000000 ~ 0x00050000 | 320 KB | `UBoot` | U-Boot 부트로더 |
| - | 0x00050000 ~ 0x00070000 | 128 KB | (예약/환경?) | 사용 안 함(경계의 연결 부분) |
| 1 | 0x00070000 ~ 0x00490000 | 4.125 MB | `kernel` | 커널 이미지(uImage) |
| 2 | 0x00470000 ~ 0x006f0000 | 2.5 MB | `initrd` | 램디스크/initrd |
| 3 | 0x006f0000 ~ 0x007f0000 | 1 MB | `JFFS2-I` | 쓰기 가능 파일시스템 |

> ⚠️ `kernel`(끝 0x490000)와 `initrd`(시작 0x470000)가 **0x20000(128KB) 겹침**.
> 원본 펌웨어의 파티션 테이블 특성으로 보이며, 플래싱 시 파티션 경계를
> 그대로 사용하되(**kernel을 0x490000 밖으로 쓰지 말 것**) initrd는 실제로
> 용량이 작아서 문제가 되지 않습니다.

### 3-2. 두 번째 ST M25P64 (8MB, SPI flash #1)

| 영역 | 오프셋 | 크기 | 레이블 |
|---|---|---|---|
| 0 | 0x00000000 ~ 0x00800000 | 8 MB | `JFFS2-II` |

### 3-3. 연결(Concatenated) 디바이스

두 개의 M25P64를 `MTD_CMDLINE_PARTS`/보드 코드에서 연결:

```
device "Flash Banks #0 #1 #2 and 3"
0x006f0000 ~ 0x00ff0000 : "JFFS2-Merge"
```

→ 첫 플래시의 JFFS2-I 영역과 둘째 플래시가 하나의 JFFS2로 붙은 구조.

### 3-4. 참고: 슬롯 워닝

```
Mismatch in Static memory mentioned and found at Memory bank 2
Memory slot 2 is empty
Mismatch ... Memory bank 3
Memory slot 3 is empty
```

스파이크(사용자 정의 저항/점퍼)로 지정한 "메모리 뱅크 2/3 있어야 한다"는
설정과 달리 보드에 그 뱅크가 없는 상태. **치명적이지 않은 워닝**입니다.

## 4. 부팅 시퀀스 (전체 흐름)

```text
[보드 전원]
   │
   ▼
┌──────────────── U-Boot 1.1.4 (0x81208800, 2008-06-17) ──────────────┐
│ 1. RAM self inspection (Simple Inspection)                          │
│     → "Error: - During Simple Inspection / Halting the System"      │
│       (첫 부팅 시 리포트되는 비칩적 오류, 이후 정상/히트키 대기)     │
│ 2. Flash 크기 확인: 8MB                                            │
│ 3. env CRC 불량 → default env 사용                                   │
│ 4. ETHERNET INITIALIZED → PHY init 실패 (워닝)                      │
│ 5. EASIC bitstream 검증 → Bad Header Checksum → 다운로드 중단        │
│ 6. In/Out/Err = serial                                            │
│ 7. "Hit any key to stop autoboot: 0" → 키 입력 시 "#" 프롬프트      │
│ 8. 부팅 이미지 0x16070000 로드 → bootm → 커널 시작                  │
└─────────────────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────── Linux 2.6.10 (uncompressed) ───────────────────────┐
│ - arch/arm 보드 초기화 (STM-spearhead)                             │
│ - 톰 메모리/MMU, interrupt, timer(66.5MHz) 설정                     │
│ - 콘솔 등록: ttyS0  (UART1)                                        │
│ - ramdisk(initrd) 0x800040에서 확인 → gzip ramdisk로 인식           │
│ - MTD/JFFS2, OHCI USB, Ethernet, RTC 드라이버 로드                  │
│ - IP-Config 실패(DHCP 없음) → 네트워크 미설정으로 넘어감            │
│ - initrd 마운트: "Mounted root (ext2 filesystem)"                  │
│ - /init → /etc/rc.sh 실행 → /root/user_setup 누락 에러               │
│ - BusyBox v1.00 ash 셸 프롬프트 `#`                                │
└─────────────────────────────────────────────────────────────────────┘
```

## 5. 부트로그 라인별 해석

### 5-1. U-Boot 단계

| 로그 | 의미 | 비고 |
|---|---|---|
| `U-Boot 1.1.4 (Jun 17 2008 - 16:42:16)` | U-Boot 버전/빌드 시각 | 1.1.4 = 2008년대 버전 |
| `U-Boot code: 81208800 -> 81239BC8` | U-Boot 코드가 RAM 0x8120~0x8123에 상주 | (커널 영역과 분리) |
| `RAM Configuration: Bank #0: 00000000 32 MB` | RAM 32MB 단일 뱅크 | |
| `Running Simple Inspection` / `Error: - During Simple Inspection` | RAM 검사기(HPI?)에서 비정상 보고 | 진단 디버그 모드 표시; 경고성 |
| `Flash: 8 MB` | SPI 플래시 인식 (M25P64) | |
| `*** Warning - bad CRC, using default environment` | env(환경변수) 저장영역 손상 | `saveenv`로 갱신 필요 |
| `ETHERNET INITIALIZED` | EMAC 초기화 완료 | |
| `Ethernet phy init failed! reset please!!` | MII PHY 초기화 실패 | 리셋/전원 순서 또는 PHY 상태 문제 |
| `Verifying EASIC bit stream` / `Bad Header Checksum` | EASIC(FPGA) 비트스트림 헤더 검증 실패 | 비트스트림 미저장/손상 |
| `Aborting the bit stream download` | EASIC 로딩을 건너뜀 | 부팅은 계속 |
| `Hit any key to stop autoboot: 0` | 부팅 카운트다운 즉시 실행 | 여기서 키 입력 → `#` |

## 6. 부팅 후 점검 명령 (현재 환경에서 바로 실행 가능)

> BusyBox 프롬프트(`#`)에서 실행. 아래 항목으로 환경 정보를 수집해 두면
> 개발환경 복원에 큰 도움이 됩니다.

```sh
uname -a                  # 커널 버전/리비전 전체
cat /proc/cpuinfo         # CPU, features, revision
cat /proc/mtd             # MTD 파티션 테이블 (파티션 덤프 위치 확인)
cat /proc/partitions      # 블록 디바이스
cat /proc/meminfo         # 메모리
cat /proc/interrupts      # IRQ 매핑
cat /proc/iomem           # 하드웨어 레지스터 맵
cat /proc/devices         # 등록된 문자/블록 디바이스
cat /proc/modules         # 로드된 모듈 (모듈형 커널인지 확인)
lsmod                     # (동일)
cat /proc/mounts          # 마운트 상태
ifconfig -a               # eth0 상태 확인
cat /proc/cmdline         # 부팅 인자 재확인
df -h                     # 루트파일시스템 용량
cat /proc/version         # gcc 버전 문자열
cat /etc/rc.sh            # 부팅 스크립트 원본 확보 ← 중요!
ls -l /root/              # user_setup 누락 확인
ls /sbin /bin /usr/bin /usr/sbin   # BusyBox 링크 목록
dmesg                     # 전체 부팅 메시지 다시 보기
```

> 이 결과물을 호스트 PC로 빼내 저장하세요(08 참고). 이후 커널/드라이버를
> 재구성할 때 필수 정보가 됩니다.

## 7. 커널/보드 포트 정보 (BSP 재구성을 위한 참고)

- 커널 머신명은 `STM-spearhead`로, 커널 소스상 `MACHINE_START(SPEARHEAD, ...)`
  형태의 보드 포트 코드가 있었던 것으로 판단됩니다.
- 이미지명의 `versatile926ejs`는 ARM versailte 실장판 기반으로 만들어진
  파생 포트임을 암시합니다 (ARM Versatile PB 926E-JS 템플릿에서 파생).
- 따라서 재구성 방향은 **versatile 템플릿 + 보드 특성(HW 레지스터맵) 포팅**
  이며, 레지스터맵은 부팅된 보드의 `/proc/iomem`, 드라이버 디스어셈블리,
  그리고 메뉴얼 07의 절차로 복원합니다.
- 공식 BSP 보유 여부는 STMicroelectronics에 문의하세요 (가장 확실한 방법).
  - ST 지원 사이트: `http://www.st.com` → SPEAr 제품군
  - 플랫폼 공개 자료(후속 아키텍처): `kernel.org/doc ... /arm/spear/overview.html`
