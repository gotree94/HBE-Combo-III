## 6.2. AMBA AHB

AHB 는 high-performance synthesizable design 조건을 총족시키는 AMBA 의 차세대 버스이다.이 버스는 다중 버스 마스터를 지원하며 고대역의 동작을 제공하는 시스템 버스이다.AHB 는 아래의 내용을 포함한 고성능, 높은 클럭 주파수 시스템을 위해 요구된 특징들을지원한다.Burst transfersSplit transactionsSingle-cycle bus master handoverNon-tri-state implementationWider data bus configurations(64/128 bits)버스의 상위레벨과 ASB/APB 사이의 연결은 어떤 시스템과도 쉽고 효과적으로 연결하여사용할 수 있다. AHB 는 하나 또는 그 이상의 bus master 를 포함하고, 일반적으로 시스템은적어도 processor 와 test interface 를 포함하고 있다.일반적인 AHB 시스템 설계는 아래의 요소를 포함하고 있다.AHB Master: bus master 는 주소와 제어정보를 제공함으로써 read 오！' write 동작을 할 수있다. 동작 시에는 하나의 bus master 만 사용되는 것이 허용된다.AHB Slave : bus slave 는 주어진 주소공간 범위 내에서 read 와 write 동작에 반응한다.Bus slave 신호는 data transfer 의 success, failure, waiting 를 동작중인 master 에게돌려준다.AHB Arbiter : bus arbiter 는 한번에 하나의 bus master 가 data transfer 를 초기화 하는것이 허용되는 것을 보장한다. Highest priority 또는 fair와 같은 어떠한 중재 프로토콜로고정되었다할지라도application의요구에따라연결될수있다.단일버스마스터시스템에서 비록 평 범해 보일지 라도, 하나의 요배 는 하나의 Arbiter 만을 포함한다.AHB Decoder : decoder 는 각 transfer 의 주소를 디코딩 하는데 사용되거나 transfer 에관련되는 slave 에 대한 선택 제어 신호를 제공한다. 하나의 slave 에 연결되는 디코딩은모든 ASB 실행에서 요구된다..AHB의 transfer에는 2가지 중요한 사실이 있다. APB 는 모든 신호의 변화는 클럭의 rising edge 에만 영향을 받는다. 이러한특징은 어떤 설계흐름에도 쉽게 융합될 수 있으며 아래와 같은 장점을 갖게 되었다.고주파 동작이 쉽게 이루어진다.클럭의 mark-space 가 독립적으로 동작해 졌다.단일 클럭 edge 를 사용함으로써 timing 분석 이 단순해 졌다.자동 테스트를 삽입함으로써 특별히 신경 쓸 부분이 없다.대부분의 ASIC 라이브러리는 rising edge 레지스터를 선호한다.Cycle 기반의 시뮬레이터와 융합이 용이해 졌다.APB 는 일반적으로 APB 의 slave device 에 적당한 형태로 전송하기 위하여, AHB 또는 ASB 의transfer 를 변환하기 위한 하나의 APB bridge 를 포함한다. 이 bridge 는 모든 주소, 데이터,제어신호를 래치 할 뿐만 아니라 APB 주변장치를 위한 slave 선택 신호를 생성하기 위해디코딩의 두 번째 단계를 제공한다.APB 의 모든 모들은 APB slave 0|q. ## 6.5. AMBA BUS 선택

위에서 설명한 AMBA 버스를 설계하려는 시스템에서 사용하기 위해서는 아래의 내용을고려해야 한다.

### (1) 시스템 버스의 선택

AHB 와 ASB 는 둘 다 시스템의 주 버스로 사용이 가능하다. 일반적으로 시스템 버스의선택은 시스템 모들의 요구에 따른 인터페이스에 의해서 결정된다. A H B 는 보다 높은대역폭의 솔루션을 제공 할뿐만 아니라 single-clock-edge protocol 은 일반적인 ASIC 개발에서사용되는 설계 자동 도구들과 보다 쉽게 연결하여 사용할 수 있기 때문에, 모든 새로운설계에 추천된다.

### (2) 시스템 버스와 주변장치 버스

모든 주변장치들을 완벽한 기능상의 AHB 또는 ASB 모들로 만드는 것은 가능하지만, 이것은아래와 같은 단점을 발생시키기 때문에 바람직하지는 않는다.주변장치 매크로 셀이 많은 설계에서 증가된 버스의 부하는 파워소모를 증가시키며성능을 저하시킨다.타이밍 분석이 필요한 곳에서는 버스상의 가장 느린 부분이 시스템의 전체 성능을떨어뜨리는 원인이 된다.파이프 라인된 신호를 전송할 때 혜택을 보는 높은 대역 폭의 매크로 셀과는 반대로,대부분의 간단한 주변장치 매크로 셀은 래치 된 주소와 컨트롤 신호를 필요로 한다.대부분의 주변장치 기능은 단순하게 선택 스트로브를 필요로 한다. 이것은 모든주변장치에 고주파 클럭 신호의 broadcast 가 필요 없이 매크로 셀의 선택과 read/write버스 동작을 전달한다.
